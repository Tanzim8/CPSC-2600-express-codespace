9. Second Normal Form: Each non non-key column is functionally depedent on the entire primary key. 
functionally depedent: means One set of attribute is uniquely determined by another set of attribute. 
Example: 
Student ID ->> StudentName
Student name functionally depedent on Student.ID BECAUSE an ID determines unique student name.

(3 NF):
There must not be any transative dependencies, which means each non key attribute must depend directly on the key. 
A>>B and B>>C means C is functionally depedent on A throug B. This is transative depency. 
Strategy: Make a new table for the attribute that is transatively dependent. It's PK should be the thing it is transatively dependent
